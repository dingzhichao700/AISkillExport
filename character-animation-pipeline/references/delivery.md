# 序列帧动画源资源交付规范

本规范是动画生成与帧动画打包工具之间的输入接口，适用于角色动作及其他序列帧动画。
不包含游戏运行时循环控制、图集生成或 Unity 集成。

## 目录

每个“动作＋朝向”为独立动画单元，目录名作为动画名称。只导出用户要求的朝向，
示例不规定朝向数量。名称建议用英文、数字、下划线，上层目录仅用于分类。

```text
outputs/
├─ delivery/
│  └─ Fighter/
│     ├─ Fly_Down/
│     │  ├─ animation.json
│     │  ├─ 001.png
│     │  └─ …018.png
│     └─ Fly_DownRight/
│        ├─ animation.json
│        ├─ 001.png
│        └─ …018.png
└─ evidence/
   └─ Fighter/
      ├─ Fly_Down/
      │  ├─ overview.png
      │  └─ provenance.json
      └─ Fly_DownRight/
         ├─ overview.png
         └─ provenance.json
```

PNG 与配置同级；不设 frames 子目录，不生成 character.json 或 action.json。
预览视频、联系表、几何配置、来源记录与中间文件放在整个 delivery 根目录之外。
下游递归查找 animation.json，只读取同级纯数字命名 PNG，并按编号数值排序。

## 分阶段交付

- 用户明确要求“先 PNG、后 JSON”时，保留上述角色/动作_朝向目录，每个动画目录只交付连续编号 PNG；不增加 frames 子目录，不生成占位 JSON。
- 在整个交付根目录之外保存源视频、采用区间、采样帧映射、实际时长、缩放和锚点记录，保证后续可补齐配置。用户要求不生成 JSON 时，这些制作记录可用其他文本格式保存。
- PNG 阶段不是可直接交给下游打包器的完整配置包。后续生成 animation.json 前，核对已有 PNG 与制作记录；不重新抽帧、缩放或擅改锚点，确需修订时另行明确范围。
- 帧数、画布、时长、缩放和 pivot 由具体资产与项目约定确定；示例和单次交付参数不升级为通用硬标准。

## 配置

animation.json 使用 UTF-8，只含以下字段（示例数值不是统一默认值）：

```json
{
  "duration": 600,
  "scale": 100,
  "pivot": {"x": 0.5, "y": 0.5}
}
```

- duration：必填，播放一次的总时长，整数毫秒，不小于帧数。使用已确认时长；
  脚本由批准的视频范围计算并取整到毫秒，抽帧数量改变不改变总时长。
- scale：打包时的缩放百分比，10～200，默认 100，导出时显式填写。
  不将视频到 PNG 的制作缩放系数写入此字段，也不提前重复应用打包缩放。
- pivot：必填，数值型 x/y，范围 0～1，相对原始未裁剪画布。
  左下角原点，X 向右，Y 向上。中心为 (0.5,0.5)，底边中央为 (0.5,0)。
  内部 geometry 的左上角像素坐标 (px,py) 转为 (px/W,1-py/H)，只转换一次。
  不同朝向可有不同数值，但需对应同一定位参考点；同一动画所有帧共用锚点。
- 不包含 action、direction、loop、source hash 或逐帧制作记录。
  动作和朝向由目录名表达，其他信息写入 evidence/provenance.json。
  循环意图仍可用于生成及审查，但不作为下游播放控制配置。

## PNG 与验收

- 从 001.png 连续编号、统一位数；超过 999 帧统一扩为四位或更多位。
- 保留真实 Alpha、半透明边缘和完整画布，不携带棋盘格或底色。
- 同一动画画布尺寸一致，围绕固定参考点对齐，不逐帧裁边或自动居中。
  不同动画可以使用不同尺寸，但角色共享几何规范要求仍需保持一致。
- 所有图片可读取，编号连续，配置合法，目录无预览图或废弃帧。
  检查透明度、完整轮廓、边缘裁切和动作连续性；结构检查不代替逐帧视觉审查。
- 交付时链接动画目录，并报告帧数、尺寸、总时长、打包缩放及锚点。

下游将每个动画打包为同名 PNG 图集和 JSON，保留相对分类目录，并均分毫秒余数。
生成 Skill 不自动执行打包，也不为适配某个图集上限擅自降分辨率或减少帧数。
