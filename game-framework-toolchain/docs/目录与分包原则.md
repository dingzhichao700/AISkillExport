# Group 分包与 Assets 目录原则

> 适用范围：Game Framework 模板、导出工程，以及 AIUI → Unity uGUI 的资源落地阶段。

## 一、权威顺序

发生冲突时按以下顺序执行：

1. 用户对本次任务的明确指令；
2. 目标工程根目录的 `AGENTS.md`；
3. 本专项规范；
4. Skill 默认规则；
5. 示例、历史记录与旧工程做法。

`AGENTS.md` 负责工程级决策和文档索引；本文件是目录、分包与 UI 资源落位的单一权威来源。不要在两处重复维护相同表格。

## 二、工程根目录与 Assets 根目录

```text
{GameProject}/
├── AGENTS.md
├── docs/
└── Project/                 Unity 工程根目录
    ├── Assets/
    ├── Packages/
    └── ProjectSettings/
```

`Packages/` 位于 Unity 工程根目录，不属于 `Assets/`。

## 三、Group 分包原则

五组是 Addressables 分包策略，不是游戏流程阶段名。游戏流程与资源打包、加载、卸载是两层概念。

| Group | Unity 组名 | 打法 | 内容 |
|-------|------------|------|------|
| `opening` | opening | Pack Together | Opening 相关运行时资源 |
| `title` | title | Pack Together | Title、Option、Setting、存档等标题域资源 |
| `default` | Default Local Group | Pack Together | 游戏内大部分 UI、公共控件、整备、HUD 等 |
| `scene` | scene | By Label `scene{id}` | 场景 Panel 与场景资源 |
| `cutScene` | cutScene | By Label | 过场 Panel 与过场资源 |

`region` 暂不纳入当前 baseline。

运行时 Prefab、`Art/atlas`、`Art/unpack`、音频等进入对应组；`Art/atlasSource`、`Art/UIReference` 和 `docs` 不进入 Addressables。

## 四、Unity 工程目录

| 工程根目录项 | 作用 |
|--------------|------|
| `Assets/Art/` | UI 参考图、图集源图、图集产物、散图、动画、音频、材质 |
| `Assets/Prefab/` | Prefab，按 Group 和模块组织 |
| `Assets/Scenes/` | `GameEntrance`、`UIEditor` 等场景 |
| `Assets/Scripts/` | C# 代码 |
| `Assets/ConfigBin/` | 运行时配置 |
| `Assets/Editor/` | 仅编辑器工具 |
| `Assets/AddressableAssetsData/` | Addressables 组与构建配置 |
| `Assets/Plugins/` | 第三方插件 |
| `Assets/TextMesh Pro/` | TMP 资源 |
| `Packages/` | UPM 依赖；位于 Unity 工程根目录 |

## 五、UI 资源路径

```text
Assets/Art/UIReference/{模块}/
Assets/Art/atlasSource/{Group}/{模块}/*.png
Assets/Art/atlas/{Group}/{模块}.png
Assets/Art/unpack/{Group}/{模块}/*
Assets/Prefab/{Group}/{模块}/{PanelName}.prefab
Assets/Scripts/csharp/com/game/{模块}/view/{PanelName}.cs
```

规则：

- 运行时模块名使用英文小写，例如 `bag`、`baglegendary`、`title`。
- 模块目录按业务模块聚合，而不是按单个界面拆分。同一业务模块内的 Prefab、图集原图、图集产物、散图和视图代码必须使用同一个模块目录；例如雷电模块的 `HomePanel` 与 `StageSelectPanel` 统一放在 `default/raiden`、`atlasSource/default/raiden`、`atlas/default/raiden.png` 和 `com/game/raiden/view`，不得拆成 `raidenhome`、`raidenstage` 等界面级目录。
- 同一模块图集内的 Sprite 名必须唯一。不同界面可以继续使用相同的局部 GameObject 名（如 `imgBg`），但图集源文件/Sprite 名应带界面或语义前缀（如 `homeBg`、`stageBg`），避免合并图集时重名。
- `UIReference` 是编辑期参考资料，可使用中文展示目录；它不等于运行时模块名。
- `opening`、`title`、`default` 通常到 `{Group}/{模块}` 两层。
- `scene`、`cutScene` 可继续按 `{id}` 分目录，并与 Addressables Label 对齐。
- `shader`、`audioMixer` 等全局资源不强制按场景 id 拆分。

## 六、图集规则

### 图集原图来源与去重

- `atlasSource` 中的实际 PNG、正式 manifest 的资源声明及 Prefab 引用关系共同决定模块图集输入；Figma“组件母版”仅用于视觉核对和资源映射，不是图集本身，也不是唯一依据。
- 每个唯一视觉资源只保留一份图集原图和一个 Sprite 名称；多个独立 GameObject 可以共同引用同一 Sprite。
- 不因左右位置、对象数量或运行时身份复制相同位图。仅当像素外观或导入设置确有差异时拆成不同原图。
- 打图集前校验重复内容、重复 Sprite 名称、无引用资源及 manifest、Prefab、PNG 三者的一致性。

| 阶段 | 路径 |
|------|------|
| 源图 | `Assets/Art/atlasSource/{Group}/{模块}/*.png` |
| 产物 | `Assets/Art/atlas/{Group}/{模块}.png` |

示例：

```text
Assets/Art/atlasSource/default/bag/*.png
→ Assets/Art/atlas/default/bag.png
```

### 图集与散图分类

- 分类依据是资源的生命周期、寻址方式和图集空间成本，不依赖具体玩法、对象名称或 Figma 分组。
- 生命周期固定、随 UI Prefab 一起加载和释放的控件、装饰及图标，默认进入模块图集。
- 需要在运行时独立创建、销毁、替换、加载或卸载，且不依附固定 UI Prefab 生命周期的图片资源，默认作为 `Assets/Art/unpack/{Group}/{模块}/` 下的散图管理。
- 全屏、超大、长条或循环使用，进入图集会明显浪费空间的图片资源，默认作为散图管理。
- 新增、迁移或重新打包图片时才执行分类判断。资源及导入设置未变化时不得重复检查；优先读取正式 manifest 的已有分类，仅在记录缺失或与实际路径冲突时检查文件。
- 日常增量校验只覆盖本次变更资源及受影响 Prefab；完整模块检查只在模块图集收口、正式交付或用户明确要求时执行，不得在每个阶段全量扫描全部图片。
- 迁移图片时必须连同 `.meta` 成对移动以保持 GUID；迁移后同步导入新路径，再统一重打模块图集、替换受影响 Prefab 引用，并同步正式 manifest 的分类、数量和关键哈希。
- 对不属于本次变更且来源不明、未引用或分类存疑的存量资源，只报告并保留，未经人工确认不得自动删除或迁移。

### 大背景资源

全屏背景、超大背景和循环滚动背景默认作为 `Assets/Art/unpack/{Group}/{模块}/` 下的散图，不进入 UI 图集。只有在完成尺寸、复用方式与图集容量评估并明确批准后，才允许作为图集输入。

### 动态数值进度资源

- 需要随运行时数值变化的进度显示不得把背景与当前填充值合成一张图片；至少拆分为固定背景/槽体和动态填充值两张独立位图。
- 每个进度类显示必须明确记录当前值、满状态值、满状态显示长度、最小安全显示长度、方向和运行时机制；显示比例统一按 `Clamp(当前值 / 满状态值, 0, 1)` 计算，再由满状态显示长度推导实际长度。
- 满状态显示长度必须来自已批准设计、Prefab 或显式配置，不得从可能已被运行时修改的 RectTransform 尺寸反推。窗口重开、Prefab 复用或对象池取出时，先恢复该显示基准，再按当前业务值刷新。
- 业务最大值与位图几何分离：最大值变化只改变比例，不改变批准的满状态显示长度。方向切分资源的最小安全长度只用于保护端帽；数值为零时必须采用明确空状态，不得把最小长度表现成仍有剩余值。
- 普通裁切或 `Image.Type = Filled` 使用的填充值应提供完整的 100% 视觉状态。背景或填充值也可采用按方向切分的可伸缩原图：横向伸缩只设置左右 Border，并保持位图高度与 Image 高度一致；纵向伸缩只设置上下 Border，并保持位图宽度与 Image 宽度一致；只有横纵两个方向都明确允许伸缩时才设置四边 Border。原图在伸缩方向上的长度无须等于最终显示长度，但必须记录不允许端帽或圆角互相挤压的最小安全尺寸。
- 图集打包必须把源 Sprite 的 Border 原样写入最终图集 Sprite，并在打包后校验 Border 一致；不得只在 Prefab 或设计说明中记录九宫格意图。
- 固定背景默认不进入 UIBinder；只导出运行时需要控制的填充层。采用方向切分填充时，通过改变填充层在进度方向上的长度、遮罩或分段结构表达数值，垂直方向尺寸保持不变；不得继续使用会裁掉必要圆角端帽的方式。
- 正式 manifest 应分别记录背景和填充资源、显示区域、内边距、方向、初始值、Border、最小安全尺寸及实际运行时实现方式。

操作要求：

1. 在 Unity Project 中选择 `atlasSource` 下的叶子文件夹。
2. 使用 `Assets → UI工具 → 合并图集`，或“合并图集（保留透明）”。
3. 不在工程外单独调用 TexturePacker 拼图集。
4. 产物目录只保留 `{模块}.png`、`.meta`，不得残留 `.tpsheet` 或多余目录层级。
5. 图集工具读取不到刚新增或迁移的源图时，应对该资源执行一次同步导入后重试；不得要求重复运行整套打包流程。
6. 源图名称集合必须与图集 Sprite 名称集合一致。
7. Prefab 或图集变化后，重新登记并构建 Addressables。
8. 同一模块包含多个 Prefab 时，应将这些 Prefab 作为一个模块批次完成收口：图集只打包一次，再统一替换和校验全部 Prefab 的 Sprite 引用；不得按界面重复生成内容相同或职责重叠的模块图集。

透明边界规则：

- 资产本身不应包含无设计意义的透明空边；应在进入 Figma/Unity 前清理。
- 需要保持 Figma 像素坐标、九宫格边界或设计留白时，打图集使用“保留透明”。
- 不依赖打图集时的 Trim 来修复按钮两种状态视觉边界不一致。

## 七、UI Prefab 落地规则

### AIUI 结构化导出

AIUI 流程在 Figma 验收后直接生成完整视觉层级，不属于传统的“空壳 Phase1”。

- Figma 是最终层级、坐标、文本框与资源摆放的权威来源。
- 图片默认使用 `UnityEngine.UI.Image`。
- 文本默认使用 `TextMeshProUGUI`，保持单行、固定设计宽高和明确位置。
- 带文本的按钮中，文本 RectTransform 不得直接拉伸为整个按钮尺寸；其高度只需略高于字号，并在按钮内按设计位置纵向居中。
- 同组状态按钮默认保持相同尺寸和视觉边界。若设计指定“仅通过文字表现选中态”，所有状态必须复用同一按钮图片，仅改变文字颜色、字号或已确认的文字效果。
- 自定义交互组件在 Unity 导出阶段映射。PoC 可暂用 `UnityEngine.UI.Button`；生产导出若工程要求 `GameButton`，必须在用户确认其类型和序列化字段后替换，不得猜测。
- 组件与脚本必须存在明确的运行时消费者或 Unity 强制依赖；不得为了“以后可能会用”而在根节点、按钮或普通视觉节点上预防性挂载 `CanvasGroup`、行为脚本或其他组件。整窗淡入淡出、统一交互开关、射线控制等需求未被结构或功能逻辑明确声明时，根节点只保留实际必需组件。
- 自定义控件只能附加其当前实现真实读取的依赖。字段仅被获取但从未参与逻辑，不构成组件挂载依据；导出后应校验组件数量，并清除已确认无消费者的冗余组件。显式需要的动画、状态或交互组件必须记录用途，不得被通用清理误删。
- Figma 审核产生的改动不静默回写 Blueprint，应记录在 handoff/export manifest。
- 非拉伸位图采用一比一尺寸链：高保真成图中的可见宽高、独立 PNG 像素宽高、Figma 组件母版与生产实例宽高、Unity `Image` 宽高必须使用同一组整数。图像模型输出的任意超采样不得原样流入图集；应在资源定稿时按生产尺寸归一化一次。
- 九宫格/方向切分、平铺、填充、遮罩和循环背景等明确可缩放资源可以让原图尺寸与显示尺寸不同，但必须在正式 manifest 中记录缩放机制、原图尺寸、显示尺寸与 Border；未声明的尺寸差异一律视为异常。
- 点击热区需要扩大时使用独立父级命中区域，不得通过放大位图画布、增加透明留白或缩放生产图片实现。
- Prefab 中所有节点的 `RectTransform` 坐标、宽度和高度必须为整数；Figma 到 Unity 的转换在边界处统一取整，并在序列化后检查，不得把小数留给人工清理。
- 进度类控件按职责命名：整体容器使用 `bar{语义}`，背景图片使用 `img{语义}Bg`，动态填充图片使用 `img{语义}Fill`，数值文本使用 `txt{语义}`。容器被运行时控制或绑定时仍使用 `bar{语义}`，不得以某个子图片的 `img...Bg` 名称代替整体结构。

### 传统空壳流程

仅当任务明确要求传统 Phase1 时，才生成空壳 Prefab、空壳脚本与 `UIBinder`；不要把该要求套用到已经完成 Figma 验收的 AIUI 完整导出。

### UIBinder 成员导出

成员导出遵循“人工决定范围、工具执行生成、最小必要集合”的边界：

- 导出会被运行时代码直接操作的交互节点，如按钮、可点击文本或容器。
- 导出需要动态控制内容、状态或显隐的节点，如 `ScrollList`、动态 Sprite、品质框和状态文本。
- 纯静态背景、标题和装饰默认不导出；只有确认存在运行时控制需求时才加入。
- `ScrollListItem` 的静态槽位底图默认不导出；物品图、品质表现等动态节点按实际需求导出。
- 人工负责确认最终节点集合；自动化可以在用户确认后配置 `uiList` 并执行生成，不得自行扩张成员范围。

生成必须复用目标工程 `UIBinderInspector` 的“一键生成绑定”逻辑，不得另写一套字段文本生成器。该生成动作必须：

1. 根据真实组件类型自动补齐所需命名空间，例如 `Image` 对应 `UnityEngine.UI`、TMP 文本对应 `TMPro`。
2. 保留生成标记之外的用户代码，不覆盖业务逻辑。
3. 对 `ScrollListItem` 模板同步同级编辑期预览克隆的 `UIBinder` 配置，并按模板内相对路径重建引用，避免对象池首次复用旧克隆时成员为空。
4. 完成后验证模板与全部池化克隆的成员数量、类型和引用均一致，并验证 Unity 无编译错误。

### ScrollList 编辑期预览 Item 数量

- `ScrollList.itemTemplate` 原则上只指向一个权威模板节点；数量可变的是同级编辑期预览或对象池 Clone。
- Prefab 中预生成的 Clone 不规定固定数量，不得把示例中的 50、100 等数量写成通用验收常量。
- 数量应足以检查视窗内的行列分布、间距、边缘和视觉还原；可为滚动衔接保留少量超出可见容量的 Item。
- 按 ScrollList 视窗尺寸、Item 尺寸、横纵间距和行列限制估算可见容量。若预生成数量明显超出视窗可容纳数量，且没有明确的对图或调试目的，应减少，以免增加 Prefab 体积、序列化、导入和初始化开销。
- 运行时数据总量与 Prefab 预生成数量解耦；较大的数据集应由 ScrollList 的对象池和滚动复用处理，不要求在 Prefab 中持久化等量 Clone。
- 人工为对比效果图临时增加预览 Item 合法，但交付 manifest 必须记录实际数量和用途。
- UIBinder 生成与校验必须遍历当前保留的全部模板和 Clone，确保成员数量、类型和引用一致；不得硬编码 Clone 数量。

### 阶段交接时看哪些文件

- `run.manifest.json` 是整个任务的总交接单，下一阶段优先读取。
- `unity/export.manifest.json` 是 Unity 阶段的详细交接单。它与总交接单共同组成当前正式交付记录。
- `Library/AIUI/*.export.json` 只是工具运行时的检查报告，可用于排查问题，但不是正式交接单。
- 名称包含 `pre-`、`backup`、`failed` 的文件或目录是历史快照，不代表当前结果，默认不得据此验收。

交接时遵循以下规则：

1. Prefab、代码、资源或成员绑定发生变化后，当前阶段必须同步更新两份正式交接单。
2. 正式交接单应记录实际数量、用途、成员导出状态、成员集合、验证结果和关键文件哈希。Stage 8 完成后不得继续记录“成员稍后导出”或空成员状态。
3. 下一阶段先核对交接单与实际 Prefab、代码和资源。两者一致时按交接单继续；不一致时以实际产物为事实来源，把交接单视为过期并先完成信息对齐。
4. 每个阶段结束时只保留一套明确的当前正式交付结果，不得让下一阶段在多个 JSON 或历史备份中猜测哪个最新。
5. 条件允许时，正式交接单写入 `artifactRole: handoff`、`authoritative: true`；临时检查报告写入 `artifactRole: diagnostic-execution-report`、`authoritative: false`。

ScrollList 数量必须分开记录：`itemTemplateCount`、`previewCloneCount`、`itemBinderCount`，以及已知时的 `runtimeDataCount`。不要用含糊的“Item 数量”代替；运行时数据量与 Prefab 预览数量无关。

一句话原则：**正式交接看 manifest，实际状态看 Prefab 和代码；两者不一致时先对齐，备份文件和 Library 报告只用于排查问题。**

## 八、最小验收

- Prefab、图集源和图集产物路径符合本规范。
- 图片和 TMP 文本数量、节点层级与批准后的 Figma 一致。
- 文本框没有被错误拉伸到按钮全尺寸。
- 图集 Sprite 名称、数量、透明边界和九宫格 border 正确。
