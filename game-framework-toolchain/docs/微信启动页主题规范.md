# 微信启动页主题规范

状态：通用基线。启动页展示机制与项目主题分离，微信平台正式导出默认安装。

## 配置与资源入口

- `Project/Assets/WeChatStartup/theme.json` 是项目主题的唯一配置源。通用模板使用中性主题；项目可以替换背景、渐变、光效、尺寸、位置、文字和标识样式。
- `Runtime/*.js.txt` 是通用运行库。进度样式变更优先改配置/素材，不复制或修改整份 SDK `game.js`。
- `ThemeAssets/` 保存项目图片，支持 PNG/JPG/JPEG/WebP；导出到 `framework-loading-skin/assets/`。配置填写小游戏包内相对路径，不写机器绝对路径或网络地址。
- `backgroundImage`、`brandingImage` 留空时继承 SDK 当前配置。没有背景图片时使用 `backgroundColor`。通用模板不携带业务项目的背景图、AppID、CDN、存档、生成包或专属版本参数。

## 可配置属性

| 配置 | 含义 |
|---|---|
| `schemaVersion` / `enabled` / `themeId` | 当前 schema 为 1；开关控制是否使用自定义外观；主题标识由项目维护 |
| `backgroundImage` / `backgroundColor` | 背景图片与缺图配置时的底色；图片按居中 cover 显示 |
| `bar.designWidth` / `widthRatio` / `height` / `bottomRatio` | 设计宽度、屏宽占比、设计高度、条顶距屏底的屏高占比 |
| `bar.trackColor` / `borderColor` / `borderAlpha` / `borderWidth` | 原生绘制槽与边框；颜色为 `#RRGGBB` |
| `bar.fillTop` / `fillBottom` | 从上到下的填充渐变；同色即可得到纯色 |
| `bar.glowColor` / `glowAlpha` / `glowLayers` | 光效配色、每层透明度、0–16 层；0 表示关闭 |
| `bar.trackImage` / `fillImage` | 可选槽图、填充图，替代对应程序绘制；填充图随进度裁切，不能随进度压缩整张图 |
| `text.fontSize` / `color` / `gap` | SDK 原文案的显示字号、配色、与条的间距 |
| `brandingImage` / `branding` | 可选标识图片以及显隐、宽高、底距；默认沿用 SDK 图标 |

图片设计需要把光晕留白与填充裁切范围一起考虑。使用已经包含光效的填充图时可关闭程序光效，避免叠加。背景替换和图片风格均按项目批准的视觉稿验收；可编辑主题不等于自动批准新美术。

## 加载行为与兼容

保留 SDK 的加载页实例、加载/编译/完成调用、返回 Promise、异常传播及原 `startGame()`。独立外观层呈现原阶段动画，不采用新的下载百分比或阶段计数算法。外观初始化不阻塞 `startGame()`；失败回退原 SDK 显示。

当前生命周期适配基于已验证的 UnityPlugin 1.3.13：原 70/90/100 阶段与动画时间不作为项目主题参数。升级 SDK 时须复核生命周期契约和原生独立探针，不把函数同名视为语义永久兼容。缺少所需接口时不接管显示；导出入口变更时明确失败。

背景和文字使用独立纹理，动态填充由 GPU 绘制；仅初始化或文字变化时上传背景纹理。使用现有屏幕 WebGL 上下文并恢复所触及的状态。标准/长屏以及退出显示必须验证，浏览器或独立 SDK 检查不能冒称完整游戏/真机通过。

## 导出与版本更新

`FrameworkWeChatBuild` 在 SDK 导出成功后调用 `FrameworkWeChatStartupSkin.Apply`，复制运行库与主题图片，并在原 `gameManager.startGame()` 前幂等安装一次。主题 JSON 转为微信可直接加载的 `theme-config.js`，不依赖小游戏 `require` JSON 支持；生成文件不作为编辑源。

后续替换背景或进度条：更新项目源图片和 `theme.json` → 正式微信导出自动重新生成资源及配置 → 校验新包显示。沿用同路径替换图片也必须将新文件带进新小游戏包；当前机制不是远端主题下载或 Addressables 内容热更，不能只改 CDN 就声称启动背景已更新。

项目应从正式框架构建入口导出。手工绕过该入口直接运行原生 SDK 导出，需要显式执行同一安装器；不得把临时手工改过的已导出包作为后续版本源。

## 差量验证

- `Tools/Tests/Test-WeChatStartupSkin.ps1` 编译并运行导出辅助类的隔离 API 夹具，验证资源复制、重复导出、背景版本替换、路径边界及 SDK 入口漂移；同时由模板静态验证调用。
- 修改运行库或主题 schema 时运行 `node Tools/Tests/WeChatStartupSkin.test.js`，验证配置与原生命周期契约。
- 主题参数化应与已验收主题对照，验证渐变或图片填充裁切，以及 WebGL 状态恢复；相关输入未变时复用匹配的既有证据。
- 实际 Unity 编译、正式微信出包、完整游戏和真机检查分别记录。标准化本身不自动授权新建样例、全量构建或发布。
