# 配置表工具链规范

## 必备目录与交付

工程根目录指包含 `Project` 的项目目录，不是 Unity 的 `Assets` 所在目录。

```text
工程根目录/
├─ AGENTS.md
├─ 文档/
│  ├─ 开发规范/                 工程开发规范 Markdown，包含索引
│  └─ 配置表/                   原始 Excel 及 Luban 定义
└─ Project/
   ├─ ConfigResource/           luban.conf、Defines、导表入口
   ├─ Tools/Luban/              锁定版本的生成器及全部依赖
   ├─ Tools/Luban.lock.json     版本、运行时要求及逐文件 SHA256
   └─ Assets/
      ├─ Scripts/csharp/login/cfg/  生成的 C#
      └─ ConfigBin/                生成的数据
```

必须提供 `__beans__.xlsx`、`__enums__.xlsx`、`__tables__.xlsx`、`GMResource.xlsx`、`SettingOptionResource.xlsx`。五张表作为获准的基础输入一起维护，新增业务表按业务需求接入，不自动复制其他样例数据。GM 表数据不等于已实现其中列出的 GM 功能。

模板的 `Templates/GameFramework/RootFiles/文档/配置表` 映射到导出工程根目录；`ProjectFiles` 映射到 `Project`。Skill 仓库的 `docs` 保留为规范源，导出映射到 `文档/开发规范`；根目录 `AGENTS.md` 的相对文档链接必须同步转换，导出工程不再并列生成旧 `docs`。

## 工具版本与路径

- 当前锁定 Luban `4.1.0+ebdb2a55680bf1c5e77be801acaab4c541862a20`，要求 PATH 中存在 dotnet 且已安装 Microsoft.NETCore.App 8.0。Unity Luban 包不能代替命令行生成器。
- 完整分发存入 `ProjectFiles/Tools/Luban`，不得只复制 Luban.dll。升级时同步锁文件、生成代码、数据及验证结果。
- `luban.conf` 中源表目录为相对自身目录的 `../../文档/配置表`；辅助定义位于 `Defines`。
- gen_json.bat、gen_bin.bat、gen.sh 保留用户确认的原版内容，不添加包装层、参数或暂停开关。脚本须从 ConfigResource 工作目录执行，原版相对路径以该目录为基准。

## 生成入口

- `gen_json.bat`：client + json + cs-simple-json。
- `gen_bin.bat`：client + bin + cs-bin。
- 两个 BAT 各自保留完整命令和末尾 pause；输出使用脚本中的固定相对路径，不接受额外输出路径参数。
- 原版 gen.sh 使用 all + json，数据输出到 ConfigResource/output，不生成 C#；其行为与 BAT 有差异，按原版保留。
- 手动运行保留 pause，成功或报错后均可查看输出。自动化由 Tools/Invoke-LubanScript.ps1 切换工作目录、仅对本次进程重定向标准输入；不改动 BAT。原版 pause 可能覆盖退出码，自动化必须检查 Luban 完成及错误日志并在失败时终止。
- JSON 与二进制读取代码必须成套使用，不能只替换数据格式。当前模板运行时仍为 JSON 基线；切换正式二进制加载时须同时调整运行时加载器并清理旧格式产物，不能只执行 gen_bin 后直接宣称可运行。
- 不手工编辑生成代码。生成的 Tables 中所有表必须登记到配置预加载清单，并由导出时的 Addressables 扫描登记到 configData。

## 验收

- 模板静态验证检查所有必备文件及生成器锁文件中的完整性哈希。
- `Tools/Test-LubanConfiguration.ps1` 将工具和源表复制到独立临时目录，从 ConfigResource 工作目录调用原版 JSON、bin 两条 BAT；验证两张基础表非空产物、Tables.cs。
- 测试的二进制产物隔离在临时目录，不覆盖模板 JSON 基线。
- 正式导出先复制源表和工具，再实际执行 JSON 生成；生成失败即终止，不允许仅凭旧配置产物、Unity 包存在或游戏能启动判定配置工具链交付完成。
- 完整 Unity 编译和 Addressables 验证仍由正式工程导出执行，导表测试不替代这些检查。
