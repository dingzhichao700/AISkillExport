# 统一资源治理发布门禁

本门禁只校验，不授予构建或部署权限。项目资源专项拥有规则、CLI、锁及 Editor Gate；发布专项维护生产入口适配。既有冻结或已部署包不回填修改，新接入只进入下一次获准输入。

## 本机绑定

`scripts/release_resource_gate.py --project <工程>` 使用 `%LOCALAPPDATA%/GameBuildTools/game-build-release/machine.json`，可由 `GAME_BUILD_RELEASE_MACHINE_CONFIG` 显式指定。无治理标记且未绑定的旧工程保持兼容；已有规则/CLI但缺绑定则阻断。绑定由管理员在已批准任务中配置，不能由候选自行指定真实源。

配置 `schemaVersion: 1`，`resourceGovernance` 数组每项含 `projectId`、`environment`、`bootstrapUrl`、`sourceProject`、`evidenceRoot`。使用 `machineSettingsFile` 指向资源专项的持久机器设置，读取其 `pythonExecutable/journalRoot/sourceProject`；也支持直接指定绝对 `python/journalRoot`。机器目录和解释器路径不写入项目共享规则。journal 必须为已批准、已存在的工程外持久目录，丢失时终止，不能创建空目录规避迁移检查。

## 执行边界

- 快照输入前完整校验；冻结及正式操作在设置 inFlight 前核对证据是否仍适用。源与候选是同一物理工程时只运行一次完整CLI。冻结后，同一工程的完整输入已由事务逐文件哈希及增删检测确认，规则、工具、绑定和排除的生成输出也未变时，复用原成功回执，不再重复运行CLI或另扫全库。生成输出变化、证据缺失/损坏等使缓存失效并重新检查；真实源未结journal每次检查。归档不要求回填历史包。
- 不同源/候选及临时历史例外继续运行各自完整检查；只声明输入未变不能替代事务验证。同输入后继可复用普通有效回执，历史例外不可继承。固定完整 `Assets` 范围，不传 `--scope`、`--active-journal`、外部规则或迁移计划，不允许候选路径掩盖真实源。
- 必须复制规则、CLI、README、锁、生产 Gate/metadata、事务实现/metadata、TexturePackerTool 和 AddressablesAutoBuilder 及 Editor 依赖。适配保守复制源工程完整 Editor 代码/程序集配置/metadata 和治理 Tools 文件；专项 Review 入口可不带。快照 manifest 必须覆盖这些文件，不能用排除项漏掉 Tools。
- 源/候选依赖哈希一致且 CLI 0 才继续；2 表示违规，3 表示规则、依赖、解释器或证据错误，均终止。legacy/warnings 保留到报告，不认定旧基线已治理完毕。回执在本机配置 evidenceRoot 下，不写 build 根。
- 失败发生于冻结或 inFlight 状态提交之前，不写 Unity 请求或发布指针；处理真实问题后按原授权重检。不得为了门禁测试实际构建、上传或激活。

## 独立验证

运行 `B0_TEST_REFERENCE=<已安装规则工程>` 对应环境配置后，以 Python 执行 `scripts/test_release_resource_gate.py`。夹具复制真实锁定CLI及依赖，建立自洽的最小测试策略/锁，不借用缺少配套资源的正式业务清单，不修改正式策略。验证正常、缺CLI、坏规则、违规新增、真实源未结journal、锁篡改、依赖遗漏、范围缩减及执行前阻断，并用真实CLI验证同源复用及生成输出变化失效。`test_release_reuse.py`覆盖缓存失效条件，事务和临时例外测试保持。正式只读CLI联验和Editor测试分别记录，不能互相代替。

## 明确批准的单事务历史例外

默认退出2/3仍阻断。只有用户明确批准具体历史项时，才在本机绑定的transactionExceptions中登记审批文件路径及SHA256；审批文件绑定唯一事务、原请求/批准消息、精确候选路径、历史交付归档哈希和唯一允许的运行时补丁。新增运行时文件或任何未授权字节变化均拒绝。

真实源全范围检查不使用例外。候选同样运行当前锁定CLI全范围检查并保留原始exit2报告；仅当全部错误与批准项的code/path/GUID/消息/关联路径及文件SHA精确匹配时，适配层记录本事务允许的历史项。exit3、任何新增/变化/缺少的错误都阻断，不退回旧规则、不缩scope、不改永久policy。仅声明CLI退出0或已有旧基线不能替代这一批准。

冻结及每个正式步骤显式传入同一事务ID。事务必须为已登记的content/build-publish且未终结；failed须先按恢复证据接续，delivered/cancelled/superseded自动使例外失效。归档交付后移除本机临时引用并保存失效验证；不得将历史项升级为全项目永久例外。没有此类已批准临时登记的项目保持原门禁行为。


## 精确归档的仅发布模式

已成功构建并归档的publish/none事务可由明确批准的本机archivedPublish绑定启用：固定候选路径、事务ID、原成功归档事务及证明SHA、源码/生成归档SHA、完整候选清单和产物SHA。候选按归档配套规则执行完整Assets CLI，退出2/3仍阻断；不要求候选同步开发目录后来新增的资源或治理版本。候选未结资源事务、完整输入增删改、依赖、Base/Content、共享发布互斥、不可变资源与远端基线保护保留。未经绑定的任务继续原流程，build/content不能使用此模式。绑定不能由候选自行声明；完成后移除本次绑定，保留证据。此模式不豁免历史错误、不重建资源、不修改开发源。


## 固定归档基准的内容构建

明确获准的content/build-publish内容事务可使用本机pinnedContent逐事务绑定；要求原成功归档证明、原完整输入清单、精确候选路径、固定新输入SHA及逐文件批准源码补丁。原scope/excludes不扩大，业务资源不变，仅审定Editor验证工具可作为补充；候选执行完整严格CLI，原开发源和候选未结资源事务均仍检查，底座版本及AOT/桥接保护hash保留。使用同一生产账本，不使用publish-only归档模式执行构建，不允许generate/export；结束后移除绑定。未绑定任务原行为不变。
