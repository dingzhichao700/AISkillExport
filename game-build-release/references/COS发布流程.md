# COS 发布流程

用于已配置的公有读、私有写 COS 桶。沿用用户授权的项目目录，不修改桶权限、不删除历史资源。

工程 `buildRelease.deployment` 配置：

```json
{
  "kind": "cos",
  "bucket": "<桶完整名称>",
  "region": "<地域标识>",
  "projectSubdirectory": "<项目名>",
  "publicRoot": "https://<桶完整名称>.cos.<地域标识>.myqcloud.com/<项目名>/"
}
```

`bootstrapUrl` 等于 publicRoot 加 bootstrap.json；`cdnRoot` 为本项目本地候选资源目录。适配器当前支持 COS 默认 HTTPS 域名，其他域名需先验证适配。

COSCLI 统一位于技能仓库 `ThirdParty/COSCLI`；原始密钥和加密配置保存在用户指定的工程外专用凭证目录，并以服务、账号和用途命名。真实路径只记录在本机环境说明，不写入项目或通用 Skill。凭证不得进入 Git、包体或发布资源。脚本通过 `--coscli` 与 `--cos-config` 显式接收路径，不读取或输出密钥，不将机器路径写入通用实现。不要使用 config show 输出凭证配置。

已绑定项目正式执行先按[完整发布事务](完整发布事务.md)登记、快照基线和冻结；已绑定项目的stage/activate必须附`--transaction <ID> --owner <负责人>`，verify/snapshot保持只读。

执行顺序：

1. 按微信流程完成 generate、export，检查同一 requestId 成功。运行 validate_release.py 并归档底座、源码状态、AOT、桥接和包体。
2. `python scripts/publish_cos.py --project <工程> --coscli <程序> --cos-config <配置> --action stage`。只上传候选引用的版本资源及 Bundle；先比较远端 SHA256，相同复用，不同拒绝覆盖；新文件使用禁止覆盖上传，再以匿名 HTTPS 下载比对。
3. 候选完整核验后执行 Invoke-GameBuild.ps1 的 publish-local，并执行 validate_release.py --published。
4. 同样参数运行 `--action activate`。再次核验不可变资源后更新本底座 current，最后合并发布 bootstrap，保留其他底座映射。指针使用禁止缓存策略；不可变资源使用一年缓存。
5. `--action verify` 可只读复查远端完整资源和当前映射。收据存放工程根 `build/archives/<base>/content/<release>/receipts/cos-*.json`，脚本输出实际路径，交付记录引用该路径；不再向build根层平铺版本收据。根层只保留当前交付入口，既有根层收据迁移须保哈希和旧新映射，历史日志不盲目替换；包含文件哈希，不包含凭证。

已绑定项目/环境共用持久事务账本；原.cos-publish.lock仅作为兼容旧入口的单调用附加锁，不代表全事务保护。中断保留未知步骤，先核实进程、收据和远端，再凭恢复证据接续；无超时自动删锁。激活比较冻结时线上基线并保留其他base映射；未新增远端CAS，仍需唯一发布者协作，不能替代跨机器独占。切换前后仍须由使用者验证微信真机加载，HTTP 验证不等于真机验收。

入口地址及客户端缓存协议以目标工程的《微信小游戏平台规范》为准；执行前按该协议判断是否需要重建底座。默认 COS 域名不是额外购买的 CDN 加速域名。

维护说明（2026-10-27）：根据用户确认的职责划分补充项目隔离、凭证分离和分层验收要求；本文件维护 COS 操作流程，项目维护运行协议，实例值在工程配置中管理，验收结果在项目构建记录中管理。

## 多项目共用本地资源根目录

COS可使用用户指定的本地共享根目录，每个项目独占 `<共享根>/<projectSubdirectory>/`；cdnRoot必须指向该项目子目录，不能指向共享根。共享根的绝对路径属于本机部署配置，通用规则不固定盘符。上传、版本指针操作仍限定当前项目，其他项目目录不得参与。

### 本地与远端映射

本地cdnRoot、COS对象前缀projectSubdirectory及客户端publicRoot/bootstrapUrl分别管理。上传映射为 `cdnRoot/<相对路径>` → `COS桶/projectSubdirectory/<相对路径>`；上传目录内容，不再附加一次本地项目目录名，避免出现重复项目层级。

迁移本地共享根或项目目录，不自动修改COS对象前缀与客户端URL。只有远端位置或访问地址改变才需要评估客户端地址与底座更新；仅本地路径改变且远端URL、客户端协议不变时，无需因此重建底座。小游戏包、构建归档及发布收据仍留在项目build目录。

### 迁移与旧目录退役

迁移前确认无进行中的构建或发布；保留全部历史版本及指针，迁移前后逐文件校验，再更新cdnRoot并验证候选与本地发布指针。

旧目录清理前检查现用配置和脚本引用已切换、所需历史资源与独有文件已完整迁移或归档，并确认无其他项目依赖。迁移本身不自动授权删除旧目录或历史资源；清理按用户授权的明确目录范围执行。

本地目录删除不等于旧GitHub Pages、COS对象或其他远端服务下线；远端退役另行核对旧客户端依赖与授权范围。用户自行删除时，记录操作者、目录和已知结果；未经检查的依赖、迁移完整性或远端下线不能补记为已验证。


## 远端校验复用（2026-11-18）

资源校验最多4路并行。stage仍逐文件完整下载计算SHA256；activate只消费同一事务账本哈希锚定的stage收据，候选选择与本地哈希不变、强ETag有效时发送If-None-Match条件GET。仅COS返回304且强ETag一致才复用已验字节；响应200完整SHA256校验，缺失/不匹配中止，缺ETag或收据不可信则完整下载，不按文件名、时间戳或ETag当作SHA256。verify仍全量下载。指针基线检查、current/bootstrap回读及其他底座映射保护不变。收据记录下载字节、完整下载数、条件复用数、并发数及耗时。只在本事务内复用，不引入跨版本信任缓存。接口依据：https://cloud.tencent.com/document/api/436/7753 。
