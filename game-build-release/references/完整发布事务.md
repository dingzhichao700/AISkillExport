# 完整发布事务

用于正式发布链的通用互斥、请求去重和恢复。Skill不是后台服务；项目自行绑定唯一负责人、真实请求授权和排期。

正式操作前先执行 [发起会话限制](../SKILL.md#发起会话限制正式执行前必查)。账本登记及 owner 参数只记录事务归属，不认证当前聊天身份，不能使普通会话获得执行资格；只读核查和获授权的工具隔离测试依入口规定继续。

## 配置与保护边界

在 ProjectSettings/FrameworkPlatform.json 的 buildRelease 下配置：

```json
{"releaseTransaction":{"stateRoot":"<共享事务目录绝对路径>","projectId":"<稳定工程身份>","environment":"<发布环境>"}}
```

同工程/环境的正式工程与所有隔离候选共用同一目录、身份和bootstrapUrl。目录不能按base或候选分拆。账本transactions.json持久覆盖登记、冻结、构建、部署、指针核验、归档与交付；.journal.lock只保护账本原子编辑，inFlight保护异步动作。无超时抢锁。inspect不创建目录。

已配置releaseTransaction的项目，升级后的Invoke-GameBuild和COS stage/activate强制要求事务参数，缺参数或畸形绑定即拒绝；未绑定且未传事务参数的其他项目保留既有流程与单调用保护，不能据此声称已获得完整事务保护。未绑定却显式传事务参数则报错，不静默降级；inspect、WhatIf、COS verify/snapshot保持只读。旧工程转发器须增加TransactionId/Owner/PythonExecutable参数，可使用assets中的转发器做增量迁移，不能覆盖项目定制逻辑。PythonExecutable可显式传入可用Python3.10+，不要依赖未配置的Windows商店别名。

**技术覆盖**：同共享目录的受控入口全事务串行、按来源身份去重、冻结排批、声明源范围变更检查、已完成步骤禁止重做、未知操作拒绝重试、COS激活前线上指针哈希比对及其他base映射保留。

**协作覆盖**：负责人确认真实授权/语义兼容、源范围及排除项完整、精确归档、Unity/batch/其他部署入口使用同事务。直接执行Unity方法、另设账本或绕过工具的COSCLI不受此锁强制控制。远端没有新增CAS或分布式租约；检查与写入间仍有外部写入竞争窗口，不能宣称平台全账户防绕过或跨机器原子切换。Git Pages沿相同事务登记/冻结/归档规则协调，但其手动git步骤没有COS适配器的自动指针硬保护，须执行者前置回读并独占写入。

## 可执行入口

以下均为脚本参数示意，绝对路径由工程提供；不隐含运行真实发布授权。

1. `release_transaction.py --project <工程> --action register --request <请求.json>`。请求包含requestId、messageId（原始真人消息）、source（来源会话）、text（真人原话/限制）、target（本批目标）、intent和buildKind、changes（完整增量列表）。intent为build/content/build-publish/publish/rollback；buildKind为base/content/none。publish/rollback必须none，content必须content。冻结前仅同target/intent/buildKind合并；不同增量全部保留。相同requestId或原始messageId关联同事务，载荷冲突拒绝，不能按文本相似度吞不同请求。转交者复用原始身份；重复消息的新ID须先由负责人关联原requestId。冻结后新需求自动登记下一批，不自动启动流水线。
2. 用`publish_cos.py --project <工程> --action snapshot --base <目标base> --output <baseline.json>`读取bootstrap及所有已映射base/current（含尚不存在的目标base）。输出只有指针哈希，不读凭证、不上传；HTTP错误不可当空基线。
3. `release_transaction.py --project <隔离工程> --action snapshot-input --scope Assets --scope Packages --scope ProjectSettings --exclude <本项目已审查的生成目录> --output <input.json>`生成源清单及candidateSha256。--exclude可重复，记录排除原因在交接；构建会改的生成DLL/AOT/版本输出须明确排除，业务源码/资源不可随意排除。清单输出放源scope之外；读取精确候选，不把正式旧Library当输入。冻结与执行入口还强制清单project绑定实际执行工程，禁止跨候选误用；每个受控动作核验清单本身、所列文件及声明范围内的新增/删除；这不验证未声明或明确排除的输入，负责人须核对完整范围。
4. `release_transaction.py --project <工程> --action freeze --transaction <ID> --owner <负责人> --candidate <清单SHA256> --input-manifest <input.json> --baseline <baseline.json>`。冻结锁住整环境；前序未完成/未知失败或较早排队请求未处理则拒绝。候选清单/哈希、线上基线、请求增量、owner记录在账本。
5. Unity动作通过`Invoke-GameBuild.ps1 -ProjectPath <工程> -Action <动作> -TransactionId <ID> -Owner <负责人> -PythonExecutable <Python>`。写pending前先登记inFlight，返回requestId。完成后执行`release_transaction.py --project <工程> --action complete-unity --transaction <ID> --owner <负责人> --operation <requestId> --evidence <本次结果JSON>`；身份及终态必须匹配，错误/未知不释放。不要手工再次begin同一Unity动作。
6. 候选校验及兼容性门禁继续执行。COS stage/activate加`--transaction <ID> --owner <负责人>`；同一事务内自动begin/finish，资源验证与指针回读证据进入步骤记录。stage绑定完整manifest/settings/catalog/bundle哈希，activate必须是同一候选；activate重核冻结基线，校验全部不可变文件后再核基线，写current后再查其余指针，合并bootstrap保留其他base。仅内容buildKind禁止generate/export；build/content意图禁止stage/publish-local/activate；publish/rollback意图禁止暗中重建。
7. 完成精确归档时用`--action begin --step archive --operation <新ID>`登记；归档证明JSON包含transactionId、candidateSha256、files（每项path及sha256）。执行`--action complete-archive --operation <ID> --evidence <归档证明>`逐文件验哈希后结束。最后`--action deliver --evidence <交付JSON>`；要求构建/激活及归档步骤存在，进入delivered-pending-acceptance并释放环境供下一批。技术交付不等用户阶段/真机验收。

## 恢复、取消与回退

- 已完成步骤同一事务不可重复。终态重复来源只返回旧事务，不重新构建。冻结前撤销用`--action cancel --transaction <ID> --evidence <撤销依据>`；该入口不取消已在运行的事务。
- 已有有效候选时，恢复以继续缺失步骤为默认，不以事务换号为重建理由。后继重新冻结相同输入、核对目标底座及候选文件后，可直接stage→publish-local→activate；原构建成功回执及来源事务写入原交付/归档，不伪造后继content/export步骤。stage绑定当前候选完整哈希，activate核对同一候选及新冻结线上基线。候选丢失、输入不匹配或实际构建失败才需要重建；已成功上传资源仍由stage自动哈希复用。
- 超时、异常或进程不明保留inFlight和failed状态。先核实owner、Unity/CLI真实进程、pending/result、产物、指针及收据；不按时间自动删锁。账本编辑锁残留也先人工核实实际进程，不自动删除。
- 恢复证明包含transactionId、owner、operationId、processesStopped:true、pointersReviewed:true及实际检查证据。`--action resolve --evidence <证明>`仅在确定未完成且可安全重试时使用；已实际完成但收据写入中断用`--completed`登记成功，防重复动作。证明为执行者复核结果，工具不代替进程/远端事实核查。旧基线变化拒绝激活后不得仅resolve然后盲重试：重新审候选与范围，需要换基线时用`--action supersede --transaction <旧ID> --owner <负责人> --evidence <恢复证明>`，证明另含reason并明确核对inFlight operationId；原事务保留为superseded，增量和来源完整复制到registered后继。后继须重新审源清单并freeze新基线才能运行；不改写冻结基线冒充原批准。
- 回退仍先只读验证明确历史manifest/Catalog/Bundle/兼容base。当前不新增自动回退指针命令；执行者在同一事务中保护手动回退，保留当前指针及验证证据，禁止用publish-local冒发最新版本。未完成回退适配时不要声称回退有与COS activate相同的全自动硬保护。
