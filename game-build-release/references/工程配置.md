# 工程配置

权威配置位于 Unity 工程的 `ProjectSettings/FrameworkPlatform.json`。普通模板由 Set-GameFrameworkPlatform.ps1 创建；旧工程接入时从现有有效设置提取，不填示例值冒充真实配置。

```json
{
  "platform": "WeChat",
  "bootstrapUrl": "https://cdn.example.com/my-project/bootstrap.json",
  "cdnRoot": "<本项目候选资源绝对路径>",
  "appId": "<实际微信 AppID>",
  "buildRelease": {
    "bundleVirtualRoot": "http://framework-content.invalid/",
    "bootConfigAsset": "Assets/Resources/GameFrameworkHotUpdateBase.txt",
    "deployment": {
      "kind": "git-pages",
      "repositoryRoot": "<资源仓库绝对路径>",
      "projectSubdirectory": "my-project",
      "remote": "origin",
      "branch": "<实际发布分支>"
    }
  }
}
```

- Git Pages 部署的 cdnRoot 必须指向本项目目录，不是多项目仓库根；部署前验证它等于 repositoryRoot/projectSubdirectory，且解析后仍在仓库内。
- 新项目默认以用户已确认的项目名作为 projectSubdirectory，在已确认的资源仓库根下生成同名项目资源目录；保留项目名大小写，本地目录与远端 URL 路径一致。项目名来自明确的工程身份，不能把 Unity 子目录 Project 当作项目名。既有项目保留已配置的目录，未经要求不迁移。仓库根由环境配置提供，不在通用脚本中硬编码机器路径。
- AppID 是项目标识；令牌、密码等凭证不得放入该文件，使用现有登录或凭证管理。
- bundleVirtualRoot、bootConfigAsset 默认值适用于新模板；旧工程保留实际值，不能为接入 Skill 擅自改变客户端协议或强迫更新底座。
- deployment 缺失时允许本地构建，不能猜测远端目的地。当前远端流程支持 Git Pages 和 COS；COS 配置及发布顺序见 [COS发布流程](COS发布流程.md)。其他存储需补充并验证适配。
- build 输出固定为项目根的 build，符合现有 Unity 适配约束。改变输出契约须同步生产端，不能只改外部脚本。
- Set-GameFrameworkPlatform 应保留 buildRelease 扩展字段。已有工程的配置变动由调用者明确完成，Skill 检查不自动修正配置。

原项目 Tools/Build-WeChatHotUpdate.ps1 可替换为本 Skill 的 assets 同名转发器；通过 CODEX_HOME/skills 链接定位，或显式传入 BuildReleaseSkillPath。它不包含项目实例地址，不内嵌第二份实现。

新模板随生成器部署该转发器；Unity 内 FrameworkHotUpdateBuild/FrameworkWeChatBuild 负责平台实际构建。旧工程可保留已验证的适配类名，以同一队列协议接入，无须整体替换 Editor 文件。
