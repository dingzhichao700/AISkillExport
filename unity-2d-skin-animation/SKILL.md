# 角色立绘蒙皮动画制作与接入

把已批准立绘变成可编辑、可复现、在目标入口可播放的二维蒙皮动画。承接当前授权阶段，不把样例尺寸、骨数、幅度或动作数量变成通用标准。

## 制作职责与阶段交接

制作专项负责已批准输入的拆件、骨架、网格、权重、动作及可编辑交付；UI专项负责页面布局、业务资格的显示消费和装配，资源治理负责入库归属/加载合同，业务负责权威状态。既有桥接需修改时明确单写范围，不将制作授权扩大为页面或全局资源重构。

新动作按本轮约定先交原速预览，再进入依赖其批准的接入阶段；离线曲线预演、原生SpriteSkin运行预览和实际页面证据分别标注，不能以GIF替代已承诺的原生验证。复用已有接入不等于省略新动作视觉审核。交接包括源/派生映射、动作接口、绑定姿态、尺寸/Pivot、时间/重置/取消契约及已验/未验范围，详细检查见[接入与验收](references/integration-review.md)。

## 开始与选路

1. 读当前项目AGENTS、正式规范及用户批准范围。优先从AGENTS或用户给出的路径读取项目绑定；未绑定时用[输入合同](references/input-contract.md)核对实际项目，不按目录名猜角色/业务ID。绑定只索引事实源，不覆盖新用户裁决。
2. 静态形象和语义锚点须先确认，有版本/依据；未确定先完成该分支，不猜锚点后绑骨。明确允许改动的动作、图层/特效、使用端和本次产物。以批准图、动作表及实际资产自检，用户判断新的视觉取舍/阶段效果。
3. 判定本轮路线；动作已有时先复用，不重做安装/导入/全部技术验证：

| 请求 | 路线与改动范围 |
|---|---|
| 轻微呼吸/摆动，无新增遮挡 | 评估单图细分蒙皮，保护刚性区和接触点 |
| 独立手臂/武器/下颌，或明显遮挡变化 | 拆件/补绘与分层蒙皮，不用大幅拉伸冒充关节运动 |
| 已有骨架，仅改幅度/节奏 | 保留形象、锚点、骨架和消费端，只修改声明参数/曲线 |
| 已有动作，仅换新增视觉元素 | 保留本体动作及时间，制作/替换挂点特效 |
| 只接已有动画 | 检查当前资源与调用契约，再适配目标使用端 |

4. 新制作读[原生蒙皮制作](references/native-skinning.md)；大动作加读[拆件与动作](references/layered-motion.md)。有外部特效读[挂点帧特效](references/mounted-frame-fx.md)。仅接入/局部调整读[接入与验收](references/integration-review.md)。输入模板为[contract-template.json](assets/contract-template.json)，不要把空字段当作已确认。

按角色维护动作集合与共用基准；同骨架兼容的动作优先复用骨架、蒙皮与驱动，同角色不同动作的拆件、骨架或显示结构差异较大时，允许保留独立Prefab，记录拆分原因和共用部分；结构或加载契约确有差异也可拆分。不强制“一角色一个物理文件”，也不以Prefab数量推断性能；制作或评估合并时读[原生蒙皮制作](references/native-skinning.md)的“同角色多动作复用”。

## 实施要点

- 保存导入meta、绑定姿态、网格/权重、骨架引用和动作驱动；支持重新加载编辑。AnimationClip、Animator或脚本驱动按项目选定，脚本驱动不能冒称交付Clip。
- 图像生成/补绘用 `game-art-asset-pipeline` 与可用的内置Image工具；可编辑矢量/原生源按其工具处理。复用批准图，不因补一个动作重新设计角色。
- 每角色参数和项目消费策略独立维护。跨项目不默认动作数、卡牌门控、Timer或UI布局；当前项目已有接口先读后用。
- 挂点帧特效按静态效果＋角色组合 → 独立原速 → Unity组合的批准阶段接续。参考可有多张，分别声明职责。打包用 `frame-animation-packer`；界面装配/输入绑定衔接 `aiui-to-ugui`。此Skill执行蒙皮与动作专项，不吞并其他制作或业务职责。
- 改Unity前核对依赖实际安装情况、共享编辑器时段及Play现场。已有原生接入不重复安装包；项目批准本轮写入不自动允许抢停其他现场或改真实玩家数据。
- 对改动范围做几何、姿态、实际入口和生命周期检查。明确证据是独立预览、正式组件隔离数据、正常玩家入口还是目标设备；技术通过与用户视觉认可分别登记。

## 可复用只读核验

运行 `python scripts/audit_contract.py --contract <json> --binding <可选项目绑定json> --output <可选报告路径>`。

脚本仅读取输入/资产/批准证据；只在明确给出output时写报告，不启动Unity、不生成美术、不修改资产。检查源图尺寸、锚点换算/批准门槛、路线、动作时长、可选骨架快照/权重、Prefab序列化参数与声明证据。报告metadata通过不等于动作或视觉已通过，已有passed证据仅作历史复核。

- 路径相对合同所在目录解析；声明根后 `project:` / `workspace:` 路径按绑定解析。不能使用本机项目路径作为通用默认。
- Pillow可用时检查PNG可见范围/透明角；无Pillow仅读PNG头并注明未核Alpha。骨架快照未提供时明确标未检查，不推测网格/权重通过。
- 新/改脚本必须实际运行；无权限、缺少批准/输入或资源不符时报告具体项，不以准备完成冒充可实施。

## 完成阶段

交付可用资产/预览、独立参数、源与处理记录、真实驱动与导入信息、技术/视觉验收及尚缺条件。项目正式规范引用本Skill的通用方法，项目绑定保留真实路径/规则；不要在Skill复制项目规范或失败日志。只有本次必交项都有证据才结清；发布、战斗权威、配置/存档及其他角色扩展不在本Skill默认范围。
