# 输入、坐标和项目绑定

输入最少包括：角色/用途、源图和批准证据、源画布/Alpha范围、实际显示需求、语义锚点的坐标/确认依据、已有动作/骨架、允许改动范围及本次验收阶段。未定字段保留null与补齐条件，不用0表示未知。

源文件路径、源像素、UI设计单位、屏幕像素与Unity单位分别记录。连续画布左下坐标归一化为(x/W,y/H)；左上输入先转换yBottom=H-yTop。若来源使用像素索引中心，先声明转换约定。主体Alpha范围不等于画布，Sprite Pivot不等于展示根或所有骨骼的中心。

绑定包含schemaVersion、workspaceRoot、unityProjectRoot、authorityPaths和可选policySnapshot、records。路径用`workspace:`或`project:`显式根前缀，普通相对路径相对当前JSON。policySnapshot只供发现；实际实施必须读权威规范，发现冲突按用户/项目规范处理，不以快照覆盖。

合同中的confirmed与证据表示已经声明批准，不是脚本能证明真人批准；必须读取原文核实所审版本/范围。源哈希不同先判定是否批准源变更。可选prefabChecks按声明骨名/父关系和字段值读取文本序列化快照，不解析完整Unity语义。二进制Prefab或复杂变体请通过授权的Editor导出快照，不从缺字段推断通过。

源图、衍生皮肤图、拆件共享画布与锚点映射要明确。不同构图可映射同一语义锚点，不机械复制归一化数值。已有静态消费者继续用原资产；派生新导入契约注明原因，保护原GUID及像素。
