# Unity原生蒙皮制作

## 盘点与固定基准

读取项目Unity/2D Animation包锁、渲染管线、已有生成器/Prefab/调用点；按本地实际API实现，缺包才评估安装。检查Sprite源尺寸、PPU、NPOT/压缩/MipMap、SpriteMode、pivot、网格/骨骼导入与目标目录的AssetPostprocessor。不得改共用导入器来掩盖单个资源目录错误。

从绑定姿态定义根、支撑、驱动骨骼；按运动职责命名，不按样例冻结骨骼数量。把源像素换算为骨架单位，子骨骼绑定位置写相对父节点；根/外部定位与动画变形分开。骨长/坐标有单位，树不成环；不让骨架根运动暗中改变界面位置。

## 同角色多动作复用

- 先确定角色共用的静态源/语义锚点、骨架与绑定姿态，再组织动作。骨骼名称、父子关系、绑定变换/矩阵、索引映射、层序、网格权重与导入契约均须比较；同名骨骼或同画布不等于完整骨架相同。
- 兼容同骨架的动作优先共用骨架和蒙皮，通过动作状态、Clip或既有驱动切换/叠加；不为每个动作机械复制完整角色Prefab。扩展骨骼时保稳定身份和显式索引映射，旧蒙皮是否能继续绑定须验证，不能仅把数组拼接。
- 同角色不同动作的拆件、骨架或显示结构差异较大时，允许保留独立Prefab，记录拆分原因与共用部分；遮挡、蒙皮拓扑、导入/渲染契约或按需加载生命周期确有差异也可保留独立结构资产；它们仍属于同一角色的动作集合。不强制一角色一文件，也不把同一Prefab包住两套重复骨架称作完成资源复用。
- 资源共用与实例共用分开：不同页面可持有同一资源，但保留独立实例、时间相位、动作选择及取消状态。新增动作不能使仅需空闲的使用端无条件加载全部攻击图层和特效。
- 性能判断看实际活动骨骼/SpriteSkin/顶点、驱动与变形开销、纹理驻留、渲染批次、加载频率和最后释放；Prefab文件数及PNG磁盘大小只能作结构/存储信息。没有实测不声称必然省内存、减少Draw Call或更快。
- 既有已验收资产的合并先提交差异、具体目标结构、引用/加载迁移、收益代价及回退方案；获准后保护旧动作、根锚点、挂点/特效时序和实际消费者生命周期再定向验证。只读审计与规范更新不授权合并、删除、重绑或批量重做。

## Sprite/网格/权重持久化

已有工具可编辑当前骨架时复用。使用Skinning Editor，或项目版本支持的Sprite Editor Data Provider：初始化provider，按稳定spriteID设置SpriteRect及NameFileId映射，再用骨骼/网格provider保存SpriteBone、顶点、三角形和BoneWeight，Apply并重导。API细节按当前安装包核对，不修改PackageCache。多Sprite层保留稳定名字和ID，不无故重生成GUID。

网格在真实弯折区加密，脸/装甲/武器保护形状。每顶点影响索引有效、权重有限非负并归一化，无空绑定或孤点；三角索引合法，检查极值翻折/穿插和边缘。权重可以渐变，刚性零件用明确刚性骨；不要复制全画面同一规则硬套不同材质。

生成GameObject与骨Transform后，把SpriteRenderer、SpriteSkin的rootBone/boneTransforms与保存骨骼顺序绑定，禁止仅存运行内存。保存可编辑Prefab/原图/meta及角色参数。重新导入/加载后核对引用和原生变形缓冲；不必为每次小调重建骨架。

## 驱动与绘制

根据项目选择Clip或解析曲线驱动。解析驱动每次从绑定或基础姿态重算，避免累计乘旋转漂移；使用项目时间源，正确注销监听。先提交所有姿态，再让SpriteSkin变形，随后UI消费最终网格；顺序按当前组件执行时序核查。

直接SpriteRenderer渲染时保留其绘制；若项目用uGUI消费原生顶点，沿用已有MeshEffect/Graphic适配并关闭骨架SpriteRenderer的重复绘制。图像源引用/材质/颜色/Mask/CanvasGroup不丢失，加载未就绪保留静态回退。映射从源尺寸、pivot和目标等比绘制矩形计算，禁止复制角色特有的硬编码像素换算。

## 实际可执行核验

核骨树/绑定与权重→在全动作关键极值检查刚性/支撑/遮挡→检查完整循环接缝和暂停→从承诺入口加载、切卡、关闭重开。输出的检查层级明确：离线快照只能验证数据，不能证明原生SpriteSkin在当前运行确实有效。
