# 游戏 UI 参考图拆件

交付能按项目约定导入的独立素材、可编辑文字和装配清单。尊重当前审核阶段。用户只要静态部分时，标记动态区域并交静态底稿，在该阶段停下。

## 接续负责该界面的会话

沿用当前会话已识别的资料路径、项目规范、已批准版本与审核阶段。只补查影响本轮制作的原图、变更或缺项；已有可访问资料无需用户重复提交。已通过且未变化的拆件和组合直接复用，不重复切图、生成或验收；局部修正仅核受影响部分。其他界面的尺寸、素材和业务规则仅在项目明确共享时复用。

| 输入 | 用它决定什么 |
| --- | --- |
| 结构图 | 父子层级、容器范围、滚动区、重复项、控件归属 |
| 效果图 | 有效画布、几何位置、轮廓、材质、文字层次、状态视觉 |
| 设计 MD | 元素含义、显示场景、可变数据和触发条件；确认它在项目中属于正式规则还是策划参考 |

资料有出入时，把差异定位到具体元素、受影响的结果及依据，依项目现行规范和用户已确认决定处理。仅在缺项确实阻塞该元素时请求澄清，其余已确定部分继续。设计阶段只读的参考目录维持只读。

## 1. 先划定有效画布，再分类

读取项目规范、已有资源及最新批准稿。以源像素测量有效界面矩形，记录源图尺寸、矩形原点、宽高和目标画布。把旁注、红框、放大示例与状态演示区单列。它们可以说明交互含义，但只有有效界面决定缩放比例。记录等比缩放及裁切或留边策略。

先列图层表，再动像素。按实例在运行时是否会随数据、选中态、列表、语言或交互变化分类：

- **静态层**包含场景背景、容器、边框和完整底板。即使区域被文字覆盖，也应保留连续的底板。
- **动态层**包含插画实例、数字、标签、状态、遮罩及进度。固定文案若需要本地化或独立排版，也交为可编辑文字。
- 一个组件可以同时具有两类层。把“已获得 7/16”拆成底板和计数文字，把可升级箭头登记为条件显示的子图标。共用图标底板只登记一次。为每层写明父组件、上下叠放顺序、复用对象、目标形态和制作方法。对只读参考与正式规则分别标来源，样例数值不进入游戏配置。

为每层分别登记「显示行为」与「素材复用方式」。例如升级箭头由条件决定显隐，文件只交一张透明图；职业徽章共用底板，职业符号按类型替换；战力随数值刷新，显示层复用一套数字字形。对来源未明确的条件记录待绑定，避免从示例画面推定玩法。

## 组件身份与后续装配

图层分类同时记录组件身份、实例位置/数量、父子嵌套、页面归属、尺寸/外观变体及状态层；区分复用组件、页内组合和普通图片/文字子节点。共用PNG不等于共用组件，不因每个Image或文字节点存在就各建一个预制体。

衔接Unity界面设计且目标环境提供`aiui-to-ugui`时，复用其[组件与预制规划约定](../aiui-to-ugui/references/component-prefab-planning.md)和同一版组件图/结构清单，按稳定组件ID组织底板、图标、文字、锁/红点/填充等独立件，交接到Figma实例、Prefab及绑定；完整图示与映射规则由该约定单处维护。其他目标仍可独立提取并交抽象装配关系，不为单张素材额外启动Unity设计流程。

已有批准组件边界下的局部修补直接沿用原图/参数，只更新受影响记录；按对象分别继承切图、结构、装配、状态与目录布局的批准范围，不以组合稿通过替代独立拆件通过。新边界或嵌套/状态结构设计时再按本轮范围补组件示意，并纳入既有设计审核，不逐张素材新增审批。核对同一实例的独立数据/状态与共用素材，图片提取完成不能冒称实际组件/预制体复用已落实。

## 2. 先做静态底稿

固定有效画幅和已知栏位，移除指定的动态实例，补出连续背景。优先使用项目已有无字底图、分层原稿或同一来源的空白区域。需要绘制的遮挡区单独出补片，仅组合到目标位置，保留可用源像素。把补绘登记为重建候选，并保存修补范围。查看实际尺寸的接缝、透视和边缘；若生成稿改变构图，只使用通过核对的局部。把静态底稿与原图同尺寸对照，锁定后再复用。

## 3. 按元素选择提取或高保真绘制

优先复用已验收且规格相符的素材。源图轮廓完整时，从原尺寸提取真实透明边缘，保留切角、描边、柔光与内部填色。小图标与文字从底板分离。只对缺失、被遮挡或明确要求重绘的部分做高保真绘制。图像编辑使用当前可用图像工具；要求独立绘制的扁平符号可交矢量母版与透明 PNG。源图无法揭示的细节记录为待审，避免把生成内容标作原始像素。

- 图片按职责命名，交原尺寸 PNG 或项目要求的格式。记录可见范围、透明留白、显示尺寸、锚点、保持比例方式。九宫拉伸资产记录四边保护区，并用窄、宽两个尺寸检查切角。
- 文字交字符串或本地化键、字体资源、字号、字重、颜色、描边、文字框、对齐、溢出和数据来源。艺术数字按字形独立输出，列出字宽、字距、基线、组合规则及长数值适配。
- 状态层记录触发条件与互斥关系。进度拆成槽、填充、裁切和独立文字，明确零值、满值与对齐。把未知的业务字段标为待绑定；已有角色/卡面仅建立引用。
- 用户要求回填时，先组合一个代表性 item，在目标显示尺寸核对底板、图标、数字和文字，再批量铺开整页。显示用角色锚点与导入图片的中心分别记录。

## 4. 交付与验收

制作阶段负责视觉拆层、素材身份与复用关系；正式资源类型、目录、Group及分包以目标项目的资源规范和权威清单为准，不在本Skill另定路由表。交给Unity接入方时，在同一素材清单登记本批制作源/运行资源、共用/模块专用及已知目标归属；缺失的正式归属由接入方按项目规则补齐后再入库。旧资源迁移、全库去重和治理工具由项目资源主责处理，不作为本批提取或UI开发前置条件，也不擅自移动旧资产。

按项目目录约定存放图片、文本/样式清单、规则和审核图。提供 JSON 或同等结构清单：源图及有效画布，坐标方向与单位，资源 ID→文件/样式，父子层级、矩形、锚点、显示条件、来源方式和消费位置。区分源像素裁切、已有素材引用、补绘与动态数据。每项能从组件找到素材，也能从素材找到引用的组件。

验收清单分别列出独立图片、组件结构、装配样件、状态预览和页面散图，记录资源ID→组件/子层→实例/消费位置。用户要看拆件时须真正展示独立底板、内容和条件层；不能只陈列装好的成品。原色/原Alpha与灰化、锁定等状态效果分别展示，不把状态效果误判为源图损坏。浅色透明件在合适明暗底检查。

保留批准源稿、提取/装配数据和当前交付清单即可，不为可再生的每张图或下游Unity产物额外制作备份。联合aiui-to-ugui时沿用其pipeline.md的最小执行与集中核验约定，不复制第二套检查报告。

交付前由制作方按项目现行示意/比例规范完成“通过基准—本次生成结果—差异标注”核查，记录对象、位置、预期、实际、责任层与结论；保持项与已确认/待核实问题分开。尺寸/哈希齐全不等于视觉符合，非预期差异先修再交，普通自检不新增一轮用户审批。与aiui-to-ugui协作时复用其[基准、差异与候选交付约定](../aiui-to-ugui/references/review-baseline-and-diff.md)，不另维护第二套契约。

验收图从本次实际候选的节点和资源生成，记录候选与证据哈希；通过后原样交接，打包不能再次重切、替换或重新解释装配。分别记录资源完整性、结构与实例核验、视觉对照、真实工具执行、用户验收；离线图不能冒称Figma/Unity截图。导入引擎或改动正式配置仅在本轮任务包含该步骤时进行。

每个可复用组件交一份装配说明，可作为总清单的一条记录。汇集层顺序与素材引用、尺寸与锚点、拉伸或裁切方式、文本对齐、状态条件、数据来源、复用位置和对应的原尺寸组合样件。组件审核后，需要进入 Figma 结构、Unity Prefab 或运行时绑定时，将这些产物交给 aiui-to-ugui 或项目指定的接入流程。
